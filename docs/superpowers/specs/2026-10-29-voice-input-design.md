# Голосовой ввод глюкозы

Дата: 2026-10-29
Статус: реализовано

## Задача

Дать возможность записать измерение глюкозы голосом за минимальное число действий,
с обязательным подтверждением распознанного значения. Время измерения — момент записи.

Приложение не медицинское изделие, доз не считает.

## Ограничение: кнопка питания

На телефоне (Xiaomi 2312FPCA6G, HyperOS 3, Android 16) долгое нажатие питания
жёстко привязано в `miui-services.jar` к явному компоненту
`com.miui.voiceassist/com.xiaomi.voiceassistant.VoiceService`:

- пакет XiaoAI в глобальной прошивке отсутствует, поэтому жест не делает ничего;
- роль `ROLE_ASSISTANT` и `voice_interaction_service` системой игнорируются;
- значения `long_press_power_key` (`voice_assistant`, `launch_voice_assistant`)
  ведут только в XiaoAI, других значений нет;
- установить сторонний APK с `applicationId = com.miui.voiceassist` нельзя:
  `INSTALL_FAILED_USER_RESTRICTED` (проверено, с другим packageId ставится);
- установка заглушки с этим пакетом всё же прошла после подтверждения на
  телефоне, но жест всё равно не сработал: в логе с физических нажатий
  (`deviceId:3`) нет ни одного `launchVoiceAssistant`, а при удержании ~3 с
  сразу вызывается `showGlobalActionsInternal`. Строки `launchVoiceAssistant`
  появлялись только на синтетических событиях из adb (`deviceId:-1`).

Вывод: штатная привязка к питанию невозможна — функция отключена в прошивке.
Триггеры — плитка в шторке, кнопка в приложении и виджет. Спайк-код роли
ассистента удалён.

## Пользовательские сценарии

1. Шторка → плитка «Записать сахар» → экран слушает → диалог подтверждения → сохранить.
2. Рабочий стол → виджет → тот же сценарий.
3. В приложении → иконка микрофона в шапке → тот же сценарий.
4. Любой триггер при отказе в микрофоне → объяснение и переход к ручному вводу.

## Поток

```
триггер (плитка/виджет/шапка)
  → MainActivity с extra voice_entry=true (singleTop, onNewIntent)
  → VoiceEntryRequests.emit()
  → DiaryRoot: проверка RECORD_AUDIO
      нет → диалог объяснения + «Ввести вручную»
  → диалог «Слушаю…»: частичные результаты, кнопки «Готово»/«Отмена»
  → onResults
  → SpokenGlucoseParser.parse(text, unit)
      null → диалог с распознанным текстом и пустым полем ввода
  → диалог подтверждения: значение, единица, время записи, контекст, заметка
  → viewModel.add(mgdl, context, note, measuredAt = момент старта записи)
```

Время фиксируется в момент запуска распознавания (`recordingStartedAt`),
а не в момент нажатия «Сохранить».

## Распознавание

- `SpeechRecognizer`, локальный (`createOnDeviceSpeechRecognizer`) при наличии;
  иначе системный, с пометкой «может использоваться интернет».
- Язык `ru-RU`, `EXTRA_PARTIAL_RESULTS = true`, `EXTRA_PREFER_OFFLINE = true`.
- Аудио приложением не сохраняется и никуда не отправляется.
- Остановка: автоматически по тишине, либо кнопкой «Готово».

## Парсер `SpokenGlucoseParser`

Чистая функция без Android-зависимостей, тестируется на JVM.

Вход: строка распознавания, текущая единица (`ммоль/л` или `мг/дл`).
Выход: `Int?` в канонических mg/dL либо `null`.

Нормализация: нижний регистр, `ё → е`, замена `,` на `.`, удаление слов-обёрток
(«сахар», «глюкоза», «показатель», «уровень», «на», «примерно»).

Поддерживаемые формы:

| Форма | Пример |
| --- | --- |
| Цифры с разделителем | `5,6`, `5.6` |
| Два числа подряд | `5 6` |
| «и»/«запятая»/«точка» | `пять и шесть`, `пять запятая шесть` |
| «целых … десятых/сотых» | `шесть целых пять десятых` |
| Числительные | `пять`, `двадцать`, `сто двадцать` |
| Смешанные | `сахар 5 целых 6` |

Правила:

- числительные 0…999 (единицы, 10–19, десятки, сотни);
- в ммоль/л дробная часть — 1–2 цифры, значение 0.5…40.0;
- в мг/дл дробная часть отбрасывается, значение 18…600;
- если кандидатов несколько — берётся первый валидный;
- при неоднозначности решение принимает человек в диалоге подтверждения.

Диапазон проверяется существующим `Glucose.parse`, конвертация — `Glucose.mmolToMgdl`.

## UI

- `VoiceListeningDialog` — «Слушаю…», живой текст, «Готово», «Отмена».
- `VoiceConfirmDialog` — редактируемое значение и единица, строка
  «Распознано: «…»» для сверки, «Время записи: сейчас, 14:32», чипы контекста
  (по умолчанию «Другое»), пустое поле заметки, «Сохранить», «Отмена».
  Распознанный текст намеренно не попадает в заметку.
- Ошибки: «Не расслышал» (повторить), «Не понял значение» (ручной ввод),
  «Распознавание недоступно» (ручной ввод).

## Триггеры

- `VoiceTileService` (`TileService`): плитка «Записать сахар»,
  `startActivityAndCollapse` (PendingIntent на API 34+, Intent на старых).
- `VoiceWidgetProvider` (`AppWidgetProvider`, RemoteViews): одна кнопка,
  PendingIntent с `voice_entry=true`.
- Иконка микрофона в `TopAppBar` на вкладке «Дневник».

`MainActivity`: `launchMode="singleTop"`, обработка `onNewIntent`,
`VoiceEntryRequests` — `MutableSharedFlow` с буфером 1, чтобы запрос не терялся
при холодном старте.

## Тесты

JVM-тесты парсера:

- `5,6` / `5.6` / `5 6` / `пять и шесть` → 5.6 ммоль/л;
- `шесть целых пять десятых` → 6.5;
- `сто двадцать` в мг/дл → 120;
- `сахар 12` в мг/дл → null (вне диапазона для мг/дл), `12` в ммоль/л → валидно;
- мусор, пустая строка, несколько чисел, границы 18 и 600 mg/dL.

Ручная проверка на телефоне: плитка, виджет, кнопка, отказ в микрофоне,
недоступное распознавание, ошибка «не расслышал», сохранение и время записи.

## Что не делаем

- Vosk/whisper и офлайн-модели в APK.
- Роль ассистента и жесты питания.
- Калькулятор доз и медицинские рекомендации.
- Автоматическое определение контекста (до/после еды) по речи.
